## 전체 파일·USB·보존 검사

- 최종 NPZ 전체 독립 검사와 메타데이터의 샘플 수가 일치했다.
  순번 이상, 장갑/호스트 시각 역행, SDK 손실·overflow·잘못된 패킷 카운터는 0이다.
  각 스트림에서 실제 32비트 장갑 시계 rollover 7회를 통과했다.
- 녹화 구간의 새 `tag_dropped`와 `deadline_misses`는 양손 모두 0이다.
  `tag_short_writes`는 왼손 13,008,614, 오른손 17,128,098 증가했다.
  이는 이 펌웨어에서 곧바로 샘플 폐기를 뜻하지 않으며, 실제 순번과 별도로 보존한다.
  모든 장치 카운터가 0이었다고 주장하지 않는다.
- USB 관측기는 왼손 버스 59,681,840개, 오른손 버스 61,804,070개 이벤트를 파싱했다.
  녹화 구간 USB 완료 오류와 관측기 손실은 0이다. 커널 로그에도 녹화 중 USB 분리나
  리셋은 없었다. USB 관측 범위는 양손 녹화 전체를 포함한다.
- 설정, 저장 보정값, 실행 펌웨어, MCU 부팅 ID와 복구 횟수는 전후 동일했다.
- 호스트 관측 3,207회에서 전원 플래그는 계속 `throttled=0x0`, 최고 온도 59.5°C,
  최소 여유 공간 약 61.4 GB, 최대 관측 간격 10.485초였다.

이는 **샘플 누락이나 전체 수신 정지가 없는 장시간 기록**의 증거다.
매 샘플이 지연 0으로 도착했다는 측정은 아니다. 저장된 호스트 수신 시각의 최대 간격은
왼손 60.171 ms, 오른손 57.383 ms이며 SDK의 묶음 수신 시각을 포함한다.
장갑 시각의 최대 샘플 간격은 촉각 6.303 / 4.256 ms, IMU 2.573 / 2.524 ms,
지자계 8.272 / 8.288 ms였다. 평균 주파수 통과가 주기 흔들림 0을 뜻하지는 않는다.

## 보존한 실패와 판정 범위

1. 첫 시도 `attempt-0001`은 연결 후 약 57초 대기한 다음 `GET STATUS` 응답을
   3초 안에 받지 못했다. 양손 모두 녹화 시작 전 실패했으며 원인은 미확정이다.
   논리 연결을 닫고 20초 후 다시 열어 `attempt-0002`의 연속 녹화가 시작됐다.
2. 9시간 관측 창의 앞 약 27초는 녹화되지 않았다. 원본의 엄격한 9시간 판정은
   **FAIL 그대로**다. 별도 최소 8시간 판정은
   `8H_MINIMUM_CONTINUOUS_CAPTURE_PASS_WITH_RUN_FAILURES`다.
3. 종료 후 보고서 도구가 `segment-0001.log` 파일까지 USB 구간 디렉터리로 취급해
   `NotADirectoryError`를 기록했다. 실제 `segment-0001` 디렉터리의 전체 USB 검증은
   먼저 성공했다. 이것은 보고서 파일 열거 오류이며 녹화 오류는 아니다.
   별도 최소 8시간 판정기는 디렉터리만 선택하며 원본 오류 기록을 그대로 보존했다.

이전 밤의 녹화 공백과 낮 검사에서의 샘플 손실은 이번 결과로 바꾸지 않는다.
전체 SDK 무결점 또는 NTU 정식 전달 승인은 아니다. 초기 상태 조회 실패의 원인 분리,
남은 물리 재연결·움직임 검사와 실제 웹 업데이터 설치 검증은 별도 과제다.
