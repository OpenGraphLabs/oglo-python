# Stock 0.9.16 R-00023: controlled USB comparison

Recorded 2026-09-25 on Mac through one USB hub path, USB ID `68EE8F4966DC`.
The owner did not know this glove's prior failure history. Its GET FWINFO and
GET IDENT running-image digest matched stock 0.9.16:
`b1c53157df9fc259a64ebe8a2c0454d916d2c2ccac163f083335496234345897`.
All captures used pyserial directly without importing the OGLO SDK.

| Capture | Result |
|---|---|
| Receive only | Five minutes, no observed sequence loss or new device drops |
| LINK PING 1 Hz, separate writer thread | Five minutes, no observed loss |
| LINK PING 1 Hz, inline between reads | Five minutes, no observed loss |
| Nine spaces + newline, 10 Hz | Last received data at 5.944 seconds; all three streams stopped |
| Same 10 Hz whitespace after USB power reconnect | Last received data at 18.026 seconds; all three streams stopped |
| Same ten-byte whitespace, 1 Hz after another reconnect | Five minutes, no observed loss |
| Switch back to 10 Hz without physical reconnect after the preceding run | Last received data at 73.302 seconds; all three streams stopped |

The failed captures observed about twelve further seconds with no bytes, then
failed their status query. These are seven separate comparisons, not a continuous
long recording. Three failures do not establish a fleet-wide failure probability
or that every 10 Hz run must fail. The traffic is only 100 payload bytes/second.

After the first failure, a concurrent observation received zero USB bytes while
the same serial/device ID delivered changing tactile, IMU and magnetometer
payloads over BLE. This separates USB host reception from a complete MCU/sensor
halt. BLE continued, but its cadence during the concurrent probe was degraded;
continued values are not proof of normal sensor timing.

After each power reconnect, GET EVENTS recovered a TX stall record in the failed
boot. Aggregate TAG drops through failure observation/cleanup were **10,431,
10,407 and 10,414**. Previously received sequences had no gaps: a terminal silence
must be detected using progress/time coverage, not only adjacent packet numbers.

The owner chose **keep 0.9.16 and conclude**. Final reconnect restored USB queries,
with identical firmware hash, CONFIG and GET ZERO values, and a new power-on boot.
No 0.9.17 write or A/B result exists for this unit. The comparison confirms a
reproducible failure condition, not the exact first failing component or a fix
verification on R-00023. It does not invalidate the separate rc7/0.9.17
[overnight recording](2026-09-22-overnight-results.md).

Raw bytes, I/O timelines, harness copies, journal and final state are retained in
`acceptance-results/mac-stock0916-causal-20260925/` in the internal qualification
workspace, with a 150-file evidence manifest at the time of closure. A portable
[summary and source hashes](https://github.com/OpenGraphLabs/oglo-hardware/blob/main/docs/validation/2026-09-25-firmware-status-evidence.json)
connect this report to the preserved evidence. Hardware was not accessed again
while synchronizing these documents.
