## Pi L-00003 반복 검사

사용자는 과거 L-00003 보고의 증상이 **장갑 전체 데이터 수신 정지**였다고
확인했다. 첨부 대화의 재현 조건은 약 20~30분 스트리밍 후 케이블을 분리·재연결하며
반복할 때 간헐적으로 발생한다는 것이다. 이는 이번 정식 0.9.16 직접 수신 검사에서
재현한 전체 수신 정지와 같은 증상 유형이다. 제공된 과거 대화에는 USB 오류·장치 상태
기록이 없어 같은 FIFO 오류가 원인이었다고 확정하지 않는다. 특정 손가락 센서 반응
저하와도 별개다. 수정 후 같은 물리 재연결 반복 조건의 통과는 아직 입증하지 않았으며,
아래 10분 6회는 USB를 뺐다 꽂는 반복 검사가 아니다.

대상은 OGPI-004의 `OGLO-L-00003`, USB `68EE8F515624`이다.
실행 이미지는 Ubuntu 0.9.17 후보
`eddf0ca99dcd929e202464d2a9c311923e895bee95fd7aa0c5dd7ec013a01615`,
SDK는 기존 검증 wheel의 rc7이다. 설치된 15개 모듈 해시를 재검증했다.
검사 시작은 06:46:54 KST이며 이전 검사 이후 MCU 부팅·설정·zero가 유지됐다.

완료한 7회는 독립 디코딩/저장 배열 검사에서 순서 누락·중복·시각 역행,
새 장갑 내부 폐기·처리 기한 초과, 수집 구간 USB 완료 오류 및 USB 관측기 손실이 0이다.
첫 1시간 녹화는 촉각·IMU·자력계 각각 실제 32비트 시계 rollover를 통과했다.
장갑 내부 쓰기 재시도는 발생했으며 이를 손실 0과 혼동하지 않는다.

두 번째 장시간 녹화의 커널 분리 시각은 **09:34:39.090030 KST**다.
사용자는 처음 본인이 조작하지 않았다고 했고, 이후 **동료가 9시 반쯤
장갑을 뽑아 가져간 것으로 보인다**고 정정했다. 따라서 이를 확인된 자연 발생
고장이나 0.9.17 회귀로 분류하지 않는다. 물리 조작 없이 9회 완료했다는 주장도
할 수 없다. 원본 실패 상태·파일·오류는 그대로 두고 조작 설명을 별도 기록했다.

중단 파일의 촉각 603,765 / IMU 1,207,531 / 자력계 301,883개를 직접 읽어
저장된 구간의 순서 이상·중복·시각 역행이 없음을 확인했다. 최대 호스트 수신 간격은
54.218 ms 미만이다. 마지막 정상 USB IN은 09:34:39.088282 KST이며,
그 뒤 분리 시각부터 알림 endpoint의 `-108` 1건과 IN 요청의 `-2` 16건이
기록됐다. 이 관측 파일에서 기존 `-71` 오류는 없었고 USB 관측기 손실은 0이다.
종료 상태 조회가 실패했으므로 해당 구간의 장갑 내부 카운터 증분은 **미확정**이다.
USB payload prefix 기록만으로 모든 센서 값의 일치를 주장하지 않는다.

10:33에 같은 USB 식별자의 L-00003이 다시 연결된 것을 확인했다. 새 MCU 부팅이며

## Mac 재연결과 새 오른손

10:09 이후 Mac에는 L-00028만 인식됐으며 기존 R-00021은 없었다.
왼손 포트를 사용하던 로컬 촉각 비교 뷰어는 상태를 저장하고 정상 종료하여
검사 중 포트 경쟁을 방지했다. 왼손의 새 부팅과 기존 펌웨어·설정·zero 보존을 확인했다.

왼손만 대상으로 시작한 60초 녹화는 10:15:04 KST, 약 32.62초 만에 중단됐다.
이후 새 `poweron` 부팅과 설정·zero 보존을 확인했다. 사용자는 **그 시각 Mac
케이블·허브를 조작했음**을 확인했다. 이는 조작 중 중단이며 자연 발생 고장
근거나 완료된 재연결 검사 결과로 쓰지 않는다.

사용자가 이후 연결한 오른손은 **OGLO-R-00028**, USB `68EE8F4969C8`이다.
왼손은 기존 허브 위치 `2-1.3`, 새 오른손은 `2-1.4`에 있다.
새 오른손의 초기 실행 이미지는 정식 0.9.16
`b1c53157df9fc259a64ebe8a2c0454d916d2c2ccac163f083335496234345897`이다.
두 장갑 모두 신원·설정·보정값과 센서 상태를 읽어 보존했다.

새 오른손은 동일한 0.9.17 후보의 네 구간 쓰기와 esptool 해시 검증을 완료했다.
ROM에서 쓰기 전후 NVS 20,480바이트를 읽었으며 바이트 단위로 같았다
(SHA-256 `626ab235633688cab00261f5735164479ac4da81708cef2c1abd86f70a15ff04`).
사용자의 오른손 USB 재연결 후 새 부팅, 정확한 0.9.17 실행 해시, 신원과 보정값
보존을 확인했다. 왼손의 부팅·설정·zero는 오른손 업데이트 동안 유지됐다.

새 L-00028 + R-00028 조합의 60초 양손 녹화·재생과 가역 설정 변경/복원이
통과했다. 독립 배열 검증에서 왼손 60.085883초·52,572개, 오른손 60.082160초·
52,568개, 총 105,140개 샘플의 순서 누락·중복·시각 역행과 새 내부 폐기·기한
초과가 0이다. 동시에 녹화된 시간은 60.082160초다.

이 조합의 75분 녹화는 이후 R-00028의 Pi 이동으로 중단됐다. 오른손은
3,586.236초 후 오류로 끝났고 왼손은 3,598.403초에서 취소됐다. 75분 완료나
NTU 전달 승인을 뜻하지 않는다. Mac에는 독립 USB 완료 관측기가 없어 USB 오류
건수 0을 주장하지 않는다. 실패 원본과 69개 파일을 검증한 압축본을 보존했다.
실패 종료이므로 일시 정지했던 로컬 촉각 뷰어는 자동 재시작하지 않았다.
