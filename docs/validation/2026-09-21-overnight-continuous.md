## 초기 실패와 현재 녹화의 구분

첫 시도는 SDK 연결 후 예정 시각까지 약 57초 기다렸다가 녹화를 시작하려는 시점에
양손 모두 `GET STATUS` 3초 timeout으로 실패했다. 녹화 파일이 생성되기 전의
실패이며 원인은 미확정이다. 연결 종료 후 재조회에는 응답했고 같은 부팅·보정·설정이
유지됐다. 이를 SDK 또는 펌웨어의 원인으로 단정하지 않는다.

자동 감독기가 실패 원본을 `attempt-0001`에 남기고 20초 후 논리 연결을 다시 열었다.
두 번째 시도 `attempt-0002`에서 실제 녹화가 시작됐고, 양손의 3개 데이터 스트림에
저장 chunk가 생기고 증가하는 것과 독립 디코딩이 실제로 진행됨을 확인했다.
현재 녹화를 중단하거나 다시 시작해 실패를 지우지 않았다.

초기 실패가 있으므로 전체 실행을 무결점 통과로 바꾸지 않는다. 원래의 엄격한
9시간 판정은 초기 실패와 부족한 시간을 그대로 보고한다. 별도의 후검증은 사용자가
요청한 8~9시간 범위에 맞춰 **단일 episode의 양손 중첩이 최소 8시간인지**를 판정한다.
해당 결과가 통과하더라도 초기 실패와 이전 불합격, NTU 전달 잔여 조건은 유지된다.

## 자동 감독과 증거

Pi systemd에 서로 독립적인 양손 감독기, 감시기, USB 버스 2/4 관측기, 종료 후 시간
판정기가 실행된다. 공통 이름은 `oglo-overnight9h-20260921-*.service`다.
SSH나 Mac 세션이 끊겨도 Pi 프로세스는 계속 실행된다. Pi 전원 상실까지 보장하는
구성은 아니며, 전원/네트워크로 확인할 수 없는 구간을 정상 수신으로 간주하지 않는다.

- 양손은 각각 하나의 긴 `oglo.record()`를 실행한다. 한 손 오류로 반대 손을 취소하지 않는다.
- 오류가 생기면 원본과 예외·시간·상태를 보존하고 20초 후 논리 연결을 재시도한다.
  USB/MCU 강제 reset, 펌웨어 쓰기, 보정 변경은 하지 않는다. 재시도 사이의 수신 공백은
  연속 녹화로 합치지 않는다.
- SDK의 5초 수신 정지 감지와 별개로, 120초간 새 저장 chunk가 없으면 부분 파일 보존을
  위한 종료를 요청한다. 저장 실패가 장시간 지속되면 강제 종료 사건도 별도 기록한다.
- 감시기는 약 10초마다 실제 저장 chunk를 읽어 순번 누락/중복/역행, 장갑/호스트 시각,
  rollover, 손실 표시, 값의 유한성·범위와 저장량을 확인한다. 실행 시간이나 PID만으로
  수신 시간을 대신하지 않는다. USB 완료 상태·관측기 손실, 전원·온도·메모리·디스크도
  기록한다. 저장 공간이 8 GiB 아래로 내려가면 디스크 보존을 위해 녹화를 멈추는 예외가 있다.
- 종료 후 최종 NPZ 전체, 양손 중첩 시간, USB 수집 구간, MCU 부팅·설정·보정 보존을
  검사하고 SHA-256 manifest와 압축본을 만든다. 8시간 판정은 USB 관측 구간의 전체
  포함 여부와 관측 공백도 확인한다. 초기 포트 열기/닫기의 USB 취소 완료를 실수신
  구간 오류와 혼동하지 않는다.
- Mac에는 별도 읽기 전용 관측기와 절전 방지 프로세스를 띄웠다. 상태를 복사하고,
  종료 압축본을 내려받아 전체 파일 해시를 검증한다. Mac의 관측 오류는 Pi 녹화를
  중지하지 않으며, 확인 불가로 표시한다.

새 감독기는 모의 장치 없이 정상 chunk, 누락·중복·시각 역행·손실 표시·범위 오류,
한 손 실패 후 재시도와 반대 손 유지 동작을 검증했다. 종료 후 판정기는 정상 구간,
USB 관측 범위 부족, 반대 손 episode 부재 fixture로 확인했다. 도구 검증은 실제
장갑 장시간 검사 통과가 아니다. 이번 관측에는 수동 케이블 움직임·분리/재연결,
센서에 힘을 가하는 기능 검사와 현장 Agent 전체 파이프라인은 포함하지 않는다.
