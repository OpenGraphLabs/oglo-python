## 기록과 판정

Pi systemd 서비스가 SSH와 독립적으로 검사 순서를 실행했고, 첫 실패에서 중단했다.

- 전체 순서·종료 후 검증: `oglo-suspect-pair-suite-20260921.service`
- 자동 재시작: 없음. 처음 실패하면 다음 단계와 재시도를 중단한다.
- 각 USB 버스의 수동적 usbmon 관측으로 데이터·알림 완료 오류와 관측기 손실을 기록한다.
- 10초마다 USB 열거 상태, Pi 저전압/스로틀링 플래그, 온도, 가용 메모리·디스크,
  SDK의 실제 저장 chunk 수·크기·수정 시각을 기록한다. 프로세스 실행 시간만으로
  데이터 수신 시간을 대신하지 않는다.
- 각 단계가 끝나면 원본 샘플 배열 전체에서 순번·누락 표시·장갑/호스트 시각·실제
  rollover·수신 시간·양손 중첩 시간을 확인하고 설정·보정값·실행 이미지·부팅을 다시 읽는다.
- 검사 기준은 순번 누락/중복·시각 역행·새 내부 폐기/기한 초과·수집 구간 USB 완료
  오류·관측기 손실 0이다. 추가로 최대 호스트 수신 간격 1초, 최대 장갑 샘플 간격
  명목 주기의 10배를 이 조사용 한도로 둔다. 생산용 성능 규격을 정한 것은 아니다.
- 8시간 파일 검증은 배열을 한정된 크기로 읽어 장시간 데이터 전체를 RAM에 올리지 않는다.
- 원본과 SHA-256 목록을 저장한 뒤 압축본 내부 파일까지 해시를 재검증한다. Mac의 별도
  관측기가 상태를 복사하고, 종료 압축본을 내려받아 다시 검증한다. SSH가 끊기면 Mac은
  상태를 미확인으로 표시하며 Pi 검사를 재시작하지 않는다. 검사 서비스의 예기치 않은
  종료나 90초 이상 상태 갱신 중단은 Mac 관측기에 실행 경고로 남긴다.

새 검사 도구는 실제 기존 L-00003 저장 파일과 오류 주입 fixture로 확인했다.
순번 경계 누락, 시각 역행·불일치, 손실 표시, USB -71, 관측기 손실, 부족한 녹화 시간은
모두 거부했다. 한 손 실패 시 반대 손 녹화를 취소하고 두 연결을 닫는 동작도 가짜 장치로
검사했다. 이 검사 도구 검증을 실제 장갑 검증 통과와 혼동하지 않는다.
