INPUT SETUP

Connect a USB pedal or button

Studio records a left/right OGLO glove pair and camera. It accepts a button that sends keyboard keys to the focused browser page. The button can have one, three, or more switches. You can assign a different key to each action.

Quick setup

  1. Plug the USB button into this computer. Open Studio and click Connect / test USB button.
  2. Press and release each physical button. If the page shows a key code, the keyboard path works. Click Finish test.
  3. Click Change key next to an action and press that physical button. Map distinct keys for Start/Stop, Calibrate/Keep, and Discard.
  4. Enter the task description, click outside text fields, then test a short episode. Keep the page focused during collection.

Keyboard input cannot identify which physical device produced a key or detect when that device is unplugged. The page stops an active capture for review if it loses focus.

Default three-button mapping

F9 starts and stops; F10 calibrates while ready and keeps a reviewed take; F11 discards a reviewed take. One-button devices can use F9 and the on-screen review controls. Held keys and rapid repeat events are ignored.

If no key appears

Some pedals use HID or serial reports instead of keyboard emulation. Check the device manual or vendor configuration utility for an input-mode option. Studio does not decode an unknown device protocol automatically. A device-specific adapter must provide button press/release events to the local controller.

Platform notes

  • macOS: Check System Settings → Keyboard and the device's vendor utility. Test the pedal in a normal text field, then in Studio.
  • Windows: Check Device Manager and the vendor's utility. Select keyboard emulation if available and run Studio's input test.
  • Linux: Check desktop input settings and the vendor's documented mode. A keyboard-emulating device should work in a focused browser without raw USB access. HID/serial adapters may need device-specific permissions.

Supporting a new device

Record its model, operating system, browser, input mode, and observed press/release values. A native adapter should emit an input source, control ID, host receipt timestamp, press/release state, and connection/error events. It must use the same state-checked actions as the on-screen controls. Mark compatibility tested only after physical setup, repeated capture, and reconnection checks. The developer data contract and file format are described in the repository's docs/10_studio.md.
